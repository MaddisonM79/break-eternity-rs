# Design notes

How `break-eternity-rs` is put together, and the rules a change has to respect. Read this
before adding an operation.

## 1. Representation

A `Decimal` is `sign * 10^10^...^mag` with `layer` tens:

| field | type | meaning |
|-------|------|---------|
| `sign` | `i8` | `-1`, `0`, or `1`. Zero iff the value is zero. |
| `layer` | `i64` | number of stacked `10^`. `0` for ordinary floats. |
| `mag` | `f64` | at layer 0 the unsigned magnitude; at layer 1 `log10(|x|)`; at layer *n* the *n*-times iterated log. Negative `mag` above layer 0 means the value is between 0 and 1. |

`normalize()` is the single source of truth for the invariant (see its rustdoc). The short
version: zero is `(0, 0, 0.0)`; at layer 0, `mag` lies in `[1/9e15, 9e15)`; above layer 0,
`|mag|` lies in `[log10(9e15), 9e15)`; `-0.0` never survives. `tests/contract.rs` asserts this
for every value any public method returns.

### Infinity

`inf()` and `neg_inf()` are `(±1, i64::MAX, +inf)`. Storing the layer as `i64::MAX` is what
makes `Ord` fall out for free (layer is compared first). `normalize()` maps three things to
this form: an infinite `mag`, a layer above `MAX_SAFE_LAYER` (9e15, mirroring upstream's
`dLayerSafeMax`), and, for `-inf` `mag` above layer 0, zero (`10^-inf`). Internal layer
arithmetic uses `saturating_add` so overflow lands on this path instead of wrapping.

The consequence: any result that would need a layer above 9e15 becomes infinity. Upstream can
represent layers up to `1.8e308` because its layer is a float; we trade that corner of the
range for an integer layer and exact equality.

### The NaN sentinel

`(0, 0, NaN)` is the crate-internal "undefined". It is constructed only by `nan_sentinel()`
and by `normalize()` when it sees a NaN, and **it must never be returned by a public method**.
The parser's `finish()` and every `checked_*` method convert it to an error.

## 2. The three altitudes

Every fallible operation is written once and exposed three ways:

```text
pub(crate) fn tetrate_raw(...)   -> Decimal                  // JS semantics, NaN on failure
pub fn checked_tetrate(...)      -> Result<Decimal, ArithmeticError>
pub fn tetrate(...)              -> Decimal                  // panics on failure
```

**`*_raw`** is the literal port of `break_eternity.js`. It never panics and never returns
`Result`, because upstream's compound algorithms depend on NaN *propagating*: `tetrate` calls
`pow`, `layer_add` calls `slog`, `slog`'s refinement loop probes `tetrate` at heights that may
be undefined, `excess_slog` bisects on values that may be NaN. If an inner call panicked or
short-circuited, the outer search would take a different path from JS and parity would break
in exactly the places that are hardest to reason about. Inside the crate, compound ports call
`_raw` kernels (`add_raw`, `mul_raw`, `div_raw`, `pow_raw`, `log_raw`, ...) rather than the
operators.

**`checked_*`** is the boundary. It runs cheap pre-checks that can *name* the failure
(`DivisionByZero`, `NegativeBase`, `OutOfDomain`), calls the kernel, and turns any NaN that
surfaced from deeper inside into `Undefined` via `nan_to_err(op)`. A `checked_*` method must
never panic for any input, finite or infinite.

**The plain form** is `checked_*().unwrap_or_else(|e| panic!(...))`, the same convention as
integer overflow and the operator overloads. Infallible operations (`abs`, `floor`, `exp`,
`sin`, ...) have no checked twin and must be total.

### Comparison semantics on the sentinel

The ported search loops rely on JavaScript's `NaN < x`, `NaN > x`, `NaN == x` all being false.
Two rules reproduce that:

* `PartialOrd::partial_cmp` returns `None` if either side is the sentinel, so `<`, `<=`, `>`,
  `>=` are false. `Ord::cmp` stays total (the sentinel sorts as zero) because `max`, `min`,
  `sort`, and `BTreeMap` cannot return `None`. This is the one place the two disagree, and it is
  unobservable through the public API. Clippy's `non_canonical_partial_ord_impl` is allowed
  with a comment at the impl.
* `PartialEq` is bit equality, so sentinel `==` sentinel is **true**, unlike JS. Loops that
  test for convergence with `==` (tetrate's fixed-point loop, `excess_slog`'s bisection) check
  `has_nan_mag()` explicitly as well. If you port another loop, do the same.

### Error kinds

`ArithmeticErrorKind` is a best-effort classification. Pre-checks name the cause when it is
cheap to know up front; anything that NaN'd three calls deep is `Undefined`. `op` is the
outermost public method, not the kernel that failed. If a caller needs a sharper cause for a
compound op, add a pre-check to that op rather than threading context through the kernels.

## 3. Upstream parity

`tests/fixtures/parity.json` is generated by `tests/fixtures/generate.mjs` from a **pinned**
`break_eternity.js` release (currently 2.1.3; the generator refuses any other version). The
gate in `tests/parity.rs` is zero mismatches. Where we deliberately answer differently the case
is matched by a rule in `deliberate_divergence()` with a written reason. The current rules are
all places where the JS answer is a quirk rather than a definition:

| case | JS | here |
|------|----|------|
| `x mod 0`, `0 ^ negative`, zeroth root | `0` / `x` | `DivisionByZero` |
| floored mod of an exact multiple with opposite signs | `±|b|` | `0` |
| `sqrt` of a negative above layer 0 | sign-mangled value | `OutOfDomain` |
| gamma / factorial of a negative above layer 0 (always an integer) | `exp` of it | `OutOfDomain` |
| `layer_add` of a negative value on a base ≤ `e^(1/e)` | numerical noise | different noise |

Two *improvements* that stay inside tolerance and so need no rule: layer-0 `pow` uses `powf`
directly when the result is a normal float (`2^10` is exactly `1024`), and integer
factorials up to `171!` are exact products rather than Stirling sums.

Do not loosen `PARITY_TOLERANCE` to make a case pass. Either fix the port, add a rule with a
reason, or, if upstream is wrong and the fix is small, fix it here and add the rule.

## 4. Testing layers

| suite | guards |
|-------|--------|
| unit tests in `src/` | the specific bug each fix addressed, with reference values |
| `tests/parity.rs` | agreement with upstream on 12k cases |
| `tests/contract.rs` | the three-altitude contract, normalization invariant, Display round-trip, no NaN, no unexpected panic, checked/plain agreement |
| `tests/proptest_arithmetic.rs` | algebraic identities, ordering laws, parser-never-panics fuzz |
| `tests/regression_fixes.rs` | historical regressions with JS reference values |
| `tests/wasm.rs` | the `JsDecimal` surface under node |

When you add an operation: write the `_raw` kernel, the `checked_` boundary, the plain form;
add it to `generate.mjs` and to `evaluate()` in `parity.rs`; add it to the tables in
`contract.rs`. That last step is what proves it obeys the rules above.

## 5. Performance notes

* `Decimal` is 24 bytes (`i8` + padding + `i64` + `f64`). Folding the sign into the layer's
  sign bit would make it 16; measure with `cargo bench` before bothering.
* `slog` refines its initial estimate with up to 100 `tetrate` probes; `layer_add`, fractional
  `iteratedlog`, `penta_log`, and literals like `"10^^2.5"` all sit on top of it. It dominates
  the parity run. A Newton step on the layer-0 residual would cut it substantially and is the
  first place to look if tetration-heavy code is slow.
* The layer-0 fast paths (`powf`, native `%`, direct `f64` arithmetic) mean ordinary
  idle-game math never touches the log-domain code. Keep it that way: check `layer == 0` early.

## 6. `no_std`

The crate is `#![no_std]` unless the `std` feature (default) is on, and always links `alloc`
for `String` and `Vec`. The kernels only ever call `f64` methods, so `src/math.rs` supplies a
`FloatExt` trait, backed by `libm`, with the same method names for everything `core` lacks
(`ln`, `powf`, `floor`, the trig family, ...). Inherent methods win method resolution, so with
`std` the trait is not even compiled and nothing changes; without it the same call sites
resolve to `libm`. Two rules follow:

* Use the method form (`x.ln()`), never `f64::ln(x)`, so the shim can catch it.
* New modules that call float methods need the same two-line cfg'd import the others have.
  A `cargo build --no-default-features --features libm` failure is the reminder.

Inherent impls are visible from every crate in the graph, so as soon as anything links `std`
(the test harness, a dev-dependency, `serde/std`) the inherent methods shadow the trait again
and the import is reported unused; that is why it carries `#[allow(unused_imports)]`. It also
means only a genuinely `std`-free target (CI builds `thumbv7em-none-eabihf`) proves the shim
covers everything. `math.rs` tests the `libm` paths on the host through fully qualified calls
against the `std` answers.

## 7. Non-goals (for now)

* NaN as a public value. Rust has `Result`; use it.
* Layers above 9e15. See "Infinity".
